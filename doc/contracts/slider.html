Slider state-layer rings (c5/c6 hover+focus, c9 active): all use color-mix(in srgb, var(--zk-color-primary) 16%, transparent) — the MUI visual target is 16% alpha at 8px spread (Slider.css line 184). MD3 specifies 8% hover / 12% focus; MUI diverges because 8% is too faint at 8px ring size against white. The active/drag ring (c9) expands to 14px spread at the same 16% alpha (MUI .Mui-active, Slider.css line 193). See Accepted MD3 deviations in the contract.

Default mold — vertical

vertical default
orient="vertical"
min at top,
max at bottom
Vertical slider requires explicit height on the root. ZK places min at top, max at bottom — .z-slider-area must anchor at top: 0 (not bottom: 0).

Sphere mold (mold="sphere")

sphere default
thumb: gradient sphere
same track colors c1–c2

Sphere mold adds .z-slider-sphere to the root — confirmed by Slider.ts domClass_() lines 315–316. The sphere gradient is targeted via .z-slider-sphere .z-slider-button { background: radial-gradient(...) } (contract row c10). Track contract rows c1 and c2 are identical to the default mold.

Scale mold (mold="scale", horizontal only)

scale default
+ tick marks below track
c1–c4 unchanged

Scale mold tick marks: ZK renders ticks via a CSS background-image URL in the iceblue slider.css.dsp. The Marble theme must provide a data: URI or a CSS-generated pattern (e.g., repeating-linear-gradient) instead of an external URL — the CSS-DSP toolchain does not permit external image references. Tick color should use var(--zk-color-outline-variant) for visual consistency with the track.

Value popup tooltip (drag state, c8)

popup visible
c8 inverse-surface bg
+ inverse-on-surface text
42

The popup (div#zul_slidetip.z-slider-popup) is appended to document.body at drag start and removed at drag end. It is NOT a child of .z-slider — CSS must not rely on descendant selectors from the slider root to reach it.

Knob mold (PE) — CSS color contract: k1–k5

knob default
k1 inner arc
k2 progress arc
k3 input bg
k4 input border
k5 input text
k1 inner arc: stroke: var(--zk-color-outline-variant)
k2 area arc: stroke: var(--zk-color-primary)
k3 input bg: background-color: var(--zk-color-surface-container)
k4 input border: 1px solid var(--zk-color-outline)
k5 input text: color: var(--zk-color-primary)

T3 boundary for knob arc geometry. The SVG arc path (d attribute) and stroke-width on both .z-slider-knob-inner and .z-slider-knob-area are set as inline SVG attributes by JS at runtime — they are NOT CSS-themable and must not appear in slider.css.dsp. Only stroke (color) on these two path elements is CSS-controlled. The numeric input's top, left, width, height, and font-size are also JS-controlled inline styles — CSS must only supply background-color, border, and color.
