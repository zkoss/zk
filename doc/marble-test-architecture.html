ZK 11 · Marble 主題 · 2026-10-20 現況

一行 CSS 改壞了，誰會發現？

Marble 的外觀由五層檢查把關。主力是 Playwright：每個預覽頁分區截圖、彈出層打開後截圖，並有選擇器依改動挑出該跑的測試。部分測試在本機跑；選擇器判定要全測時，由負責人決定何時跑。目前不接 CI 或 Jenkins。

靜態檢查 Playwright 回歸套件 Agent 驗證流程 Jenkins 人工審查
一 · 架構

CSS 從原始檔到被檢查的路徑

CSS 建置進 jar 之後，被三個網站載入；每個網站上各有一層檢查。選擇器讀取 git 的改動與 class 索引，決定 Playwright 要跑哪些測試。

二 · 主力

Playwright 套件裡有五類檢查

同一個預覽站，五種問法：畫面跟上次一樣嗎、換品牌色或密度還正常嗎、某個數值對嗎、頁面打得開嗎、有沒有違反無障礙或系統規則。

截圖比對

  • gallery：每頁依分區標題分區截圖，依檔名計 395 張（97 頁），新頁自動納入 每區 ≤ 20 px
  • 狀態截圖：23 個表單元件的 hover／focus／active ≤ 20 px
  • 彈出層：26 個預覽頁、56 個測試，用真實操作打開後截圖，含 toast、notification、messagebox、errorbox 10–20 px
  • tablet：iPad UA 下 58 個測試、31 張 PNG

品牌色與緊湊密度

  • brand：data-brand="copper" 下掃描全部頁面，找「沒跟著主色變」的像素；另有 15 頁分區截圖（128 個測試）
  • compact：15 頁分區截圖，加全部頁面兩種密度的控制項高度檢查（129 個測試）

數值守衛

  • 讀 getComputedStyle 與元素位置，不看圖
  • 每條守衛鎖住一個過去出過的問題
  • component-theme-variables：63 個測試確認 --zk-<元件>-* 覆寫在各元件頁生效

能不能渲染

  • smoke：119 個測試，每個預覽頁（含 inputs、overview 這類彙整頁）打開後沒有 HTTP 500、沒有 ZK compose error

無障礙與系統規則

  • hit-target 觸控尺寸、focus-scan focus ring 被裁
  • forced-colors 高對比模式；另有 99 張截圖只供人工看
  • zindex、reset、responsive、print、font-size
三 · 選擇器

只改一個元件時，只跑相關的測試

zkthemelab/scripts/select-tests.mjs 讀 git 的改動，回答「全測」「部分測」或「不測」，並輸出一個可直接執行的指令。

class 索引（zkthemelab/doc/class-index.json）由 build-class-index.mjs 產生，目前涵蓋 143 頁（115 頂層、16 個 pv/、12 個 utility/）；新增頁面後要重跑。實測（2026-10-20，共 1,692 個測試）：整檔解析 combobox.css 會選出 1,248 個，超過門檻 1,128，所以回答全測；改 token 檔也直接回答全測。只改單一規則時的選出數（1,345 個測試時：button.css 選出 646，combobox 128 個）。

四 · 流程

改一行 CSS 之後的標準流程

新元件或整個元件重做時，步驟 1 之前會先走 Agent 驗證流程：先寫 contract，Gate 1（zk-theme-evaluator）量測實作是否符合 contract，Gate 2（md3-design-verifier）判斷設計是否符合 Material Design。預覽站在 web.xml 設 5 分鐘 session 逾時，避免連跑時 ZK 每個 session 一條的 Timer 執行緒堆積（ZK-6213）。

六 · 觸發

誰按下執行鍵

GitHub Actions 不跑外觀測試

zk-build 只跑 ./gradlew clean build，並把 includeBuild（含 zkthemelab）註解掉；sync-marble-theme 只把 CSS 同步到 zkThemeTemplate。沒有任何 workflow 或 git hook 執行 Playwright。

Playwright 仍靠人在本機跑

選擇器讓本機只跑相關的測試；例如改 listbox、datebox、combobox 的一條規則，部分測 29–49 秒，約為不平行全測 380 秒的 8–13%（改 button.css 的規則則約 53%）。但沒有人跑就不會有紅燈。

規則：部分測本機跑，全測人工決定

改動後先跑選擇器。回答「部分測」就在本機跑它給的指令；回答「全測」時不自動跑，回報原因，由負責人決定何時全測。使用者機器上的 Claude Code hook（.claude/hooks/marble-select-tests.mjs，不進 git）會在 session 改到 CSS、預覽頁或 spec 的那一輪結束時自動跑選擇器。Jenkins 接線計畫暫緩。

ZATS 由核心團隊觸發

Jenkins ZK-Gradle-ZATS-Test 平日 8–19 點輪詢加手動，跑在 PR 分支上（參數 pr/N）。從 fork 開 draft PR 就能用同一個 job 跑。

來源（量測於 2026-10-20）：zkthemelab/src/test/playwright/playwright.config.ts（29 個 project）、npx playwright test --list 與 select-tests.mjs --json（1,692 個測試）、zkthemelab/doc/screenshots/（706 張非 forced-colors PNG、99 張 forced-colors 審查圖）、zkthemelab/doc/class-index.json（143 頁）、doc/contracts/（94 份 .md、19 份 .html 範本）、zktest/src/test/java（3,939 個 @Test）、.github/workflows/、zkthemelab/src/main/webapp/WEB-INF/web.xml。
