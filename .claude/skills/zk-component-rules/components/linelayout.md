# linelayout

A vertical or horizontal timeline layout that renders chronological or sequential items along a central connector line. Each `<lineitem>` child is positioned symmetrically on either side of the line, with a circular point marker at the intersection. Composite: `<linelayout>` is the container; `<lineitem>` children each render a point, a first-area slot, and a last-area slot.

ZK-EE only (ships in `zkmax.jar`).

## DOM structure

```
.z-linelayout  (.z-linelayout-vertical | .z-linelayout-horizontal)   (<div>, root; role="list")
├─ .z-linelayout-first                (<div>, first-area column; id="<uuid>-first"; role="none")
│  └─ [first-area content, moved here by each .z-lineitem via _moveSubDOMOut()]
├─ .z-linelayout-cave                 (<div>, center column; id="<uuid>-cave"; role="none")
│  ├─ .z-linelayout-line              (<div>, the continuous connector line; id="<uuid>-line"; role="none")
│  └─ .z-lineitem  (one per child)    (<div>; role="listitem"; aria-owns="<uuid>-first <uuid>-last")
│     ├─ .z-lineitem  (first-area)    (<div>, id="<uuid>-first"; VIRTUAL PARENT — moved to .z-linelayout-first)
│     ├─ .z-lineitem-point            (<div>, point circle; id="<uuid>-point"; aria-hidden="true")
│     │  └─ .z-lineitem-point-inner   (<div>, contains image or icon; id="<uuid>-point-inner")
│     └─ .z-lineitem  (last-area)     (<div>, id="<uuid>-last"; VIRTUAL PARENT — moved to .z-linelayout-last)
└─ .z-linelayout-last                 (<div>, last-area column; id="<uuid>-last"; role="none")
   └─ [last-area content, moved here by each .z-lineitem via _moveSubDOMOut()]
```

**Critical DOM mutation — virtual parents:** The lineitem mold initially places the first/last-area `<div>`s inside `.z-lineitem` in the cave. On `bind_()`, `_moveSubDOMOut()` moves them out: each lineitem's `first-area` `<div>` is moved into `.z-linelayout-first` and its `last-area` `<div>` into `.z-linelayout-last`. The `.z-linelayout-first` and `.z-linelayout-last` columns therefore contain ALL lineitems' first/last areas as siblings, ordered by lineitem position. ZK uses `makeVParent()` / `undoVParent()` to manage this detachment so the virtual parent relationship is maintained for ZK's widget tree.

**Class name note:** The first-area and last-area `<div>` elements generated by `encloseChildHTML_()` carry the class `this.$s()` which resolves to `.z-lineitem` (the base class of the Lineitem widget). They do NOT carry a distinct `-first` or `-last` class — the class on these moved `<div>` elements is simply `.z-lineitem`.

## Orientation classes

Toggled on the root `.z-linelayout` via `domClass_()` (initial render) and `_updateOrient()` (runtime). Exactly one of these is always present:

- `.z-linelayout-vertical` — default (`orient="vertical"`). The container is a row (`flex-direction: row`); the three columns (first, cave, last) stack horizontally; the connector line runs vertically down the cave center.
- `.z-linelayout-horizontal` — when `orient="horizontal"`. The container is a column (`flex-direction: column`); the three columns stack vertically; the connector line runs horizontally across the cave center.

## State classes on lineitem

- `.z-lineitem-point-hidden` — added to `.z-lineitem-point` (NOT the root `.z-lineitem`) when `pointVisible="false"`. Uses `visibility: hidden` semantics (the point still occupies space). Toggled by `_updatePointVisible()`.
- `.z-lineitem-stretch` — added to the first/last area `<div>`s (the moved virtual-parent divs) when the lineitem has `hflex` (in vertical mode) or `vflex` (in horizontal mode). Applies `width: 100%; height: 100%` to make the slot fill its column.

## Point modifier states

The `.z-lineitem-point-inner` element may carry additional classes for point content type:

- No extra class — default; no image, no icon; the inner div is an empty square rendered by CSS alone.
- `.z-lineitem-point-icon` — when `pointIconSclass` is set; the named icon class is added alongside this one. The inner div acts as an icon holder.
- `.z-lineitem-point-image` — implicit via `background-image` inline style when `pointImageSrc` is set (no dedicated class, the image is applied via `background-image` by `_updatePointImageSrc()`).

There are NO lineitem-level state classes for selected, disabled, active, or error. Linelayout and lineitem have no interactive state model — they are purely layout and display components.

## Attribute support

| Attribute | Affected element | Effect on DOM |
|-----------|-----------------|---------------|
| `orient` (Linelayout) | `.z-linelayout` root | Toggles `.z-linelayout-vertical` / `.z-linelayout-horizontal` |
| `lineStyle` (Linelayout) | `.z-linelayout-line` | Inline style applied via `_updateLineStyle()` — clears then re-applies arbitrary CSS style string |
| `firstScale` (Linelayout) | `.z-linelayout-first` | `flex-grow` set inline to the numeric scale value |
| `lastScale` (Linelayout) | `.z-linelayout-last` | `flex-grow` set inline to the numeric scale value |
| `pointVisible` (Lineitem) | `.z-lineitem-point` | Toggles `.z-lineitem-point-hidden` |
| `pointStyle` (Lineitem) | `.z-lineitem-point` | Inline style applied via `_updatePointStyle()` |
| `pointImageSrc` (Lineitem) | `.z-lineitem-point-inner` | `background-image: url(...)` set inline |
| `pointIconSclass` (Lineitem) | `.z-lineitem-point-inner` | Class added to inner div; previous value removed first |
| `opposite` (Lineitem) | Content placement | Swaps which child goes into first vs last area at `_updateOpposite()` |
| `frontSpace` (Lineitem) | all three parts | `margin-top` (vertical) or `margin-left` (horizontal) applied inline |
| `backSpace` (Lineitem) | all three parts | `margin-bottom` (vertical) or `margin-right` (horizontal) applied inline |
| `width` / `height` (Lineitem) | first/last area divs | Inline `width` or `height` applied; split by firstScale/lastScale ratio when numeric |

## Composition invariants

- **Tripartite column structure.** Every linelayout renders exactly three outer containers: `.z-linelayout-first`, `.z-linelayout-cave`, `.z-linelayout-last`. The cave holds the connector line and the row of lineitem center blocks; the outer two columns hold content.
- **Connector line fills the cave.** `.z-linelayout-line` is positioned absolutely inside `.z-linelayout-cave` and must span the full height (vertical mode) or full width (horizontal mode) of the cave. `z-index: 99` is set by ZK; the theme must not remove it or set a higher z-index on the cave background.
- **Point circles sit above the line.** `.z-lineitem-point` has `z-index: 100` (set inline by ZK via CSS). The theme must not flatten the stacking context in a way that hides points beneath the line.
- **First/last content is aligned with its corresponding point — but only if the content columns flow along the timeline axis.** Each lineitem's first-area and last-area divs are siblings in their respective columns. Alignment requires THREE properties on `.z-linelayout-first`/`.z-linelayout-last`, not just one:
  1. **`flex-direction`** matching the orientation — `column` in `.z-linelayout-vertical`, `row` in `.z-linelayout-horizontal`. This is the property most easily missed: ZK's own LESS sets it per orientation on first/last (and cave) independently. If a theme sets it only on the cave (or omits it), the content columns default to `flex-direction: row`, the slots flow on the cross axis, and **all content collapses to a single main-axis position** — the timeline visually breaks (all items bunch at one point) even though `justify-content: space-around` is present. Verified gap: doc/skill-gaps.md 2026-06-22.
  2. **`justify-content: space-around`** — distributes the slots evenly along the (now correct) main axis so each lines up with its `space-around`-distributed cave point. Works only when all lineitems have equal height; otherwise alignment relies on matched sibling order.
  3. **`align-items`** toward the cave — `flex-end` on `.z-linelayout-first` (and `.z-linelayout-cave`), `flex-start` on `.z-linelayout-last`. This pulls each content slot to the cave-facing edge so it sits *adjacent* to the connector line/points instead of floating in the middle of the column. Set on the base class (orientation-independent); the flex-direction flip handles the axis. Stock ZK uses identical values for both orientations.
- **`firstScale` and `lastScale` control the column width ratio.** JS sets `flex-grow` on `.z-linelayout-first` and `.z-linelayout-last` to the scale values. The cave column does NOT receive `flex-grow` from these properties — its width is determined by the point size and cave padding. A theme must NOT apply `flex-grow` to `.z-linelayout-cave` or it will break the tripartite ratio.
- **`opposite` swaps content sides.** When `opposite="true"`, the lineitem's first child goes into the last-area and vice versa. The DOM swap happens at `_updateOpposite()` by moving elements between first/last containers. CSS selectors cannot rely on a fixed left/right assignment for content; the point is always centered.
- **`.z-lineitem-point-inner` holds the icon/image and must center it on both axes.** The inner div is the content holder for both content types: `pointIconSclass` adds an icon class to it (the glyph renders via the theme's icon mechanism — e.g. a `::before` mask), and `pointImageSrc` sets an inline `background-image` on it. Two centering traps:
  1. **`width/height: inherit` overflows the bordered interior.** Stock ZK sizes the inner with `inherit`, which inherits the point's *computed* width/height (e.g. 24px). When the point has a border and `box-sizing: border-box`, its interior content box is smaller (24px − 2×2px border = 20px), so a 24px inner overflows it and — with the point's `overflow: hidden` — its box center sits ~half-the-border off the point center (measured +2px/+2px for a 2px border). Size the inner with `width/height: 100%` so it fills the interior exactly and centers without offset.
  2. **`background-image` from `pointImageSrc` has no `background-position`.** The default `0% 0%` anchors the image to the top-left corner of the inner. A theme that uses an image point must set `background-position: center` to center it.
  The robust, orientation-independent way to center the icon glyph is `display: flex; align-items: center; justify-content: center` on the inner — this centers an inline-block icon glyph (`::before`) regardless of font metrics, replacing the fragile stock approach of `line-height: <interior-size>` + `::before { position: relative; top/left: <offset> }` baseline tuning, which is off by any inner-overflow and tied to a specific glyph size.

## Relational invariants

- **Point circle is a true circle.** On `.z-lineitem-point`, computed `width` and `height` must be equal to within ±1px, and `border-radius` must produce a circle (≥ 50% of half the width). Non-circular points break the timeline's visual metaphor.
- **Connector line is centered in the cave.** In vertical mode, `.z-linelayout-line` left offset must equal `(cave.offsetWidth − line.offsetWidth) / 2` within ±2px. In horizontal mode, `top` offset must equal `(cave.offsetHeight − line.offsetHeight) / 2` within ±2px. The formula `calc(50% − lineWidth/2)` achieves this.
- **Line runs the full length of the cave.** In vertical mode, `.z-linelayout-line` must have `height: 100%` such that the line reaches both the first and last lineitems' point midpoints. No gap is visible above the first or below the last point.
- **Content slots do not overlap the cave column.** `.z-linelayout-first` and `.z-linelayout-last` each have `overflow: hidden`; content must not visually bleed into the cave. The cave padding (`--zk-linelayout-cave-padding` equivalent) provides the gutter between content and point.
- **Point circles do not overlap each other.** Adjacent lineitems' points must maintain a visible gap. This is enforced by the lineitem's `flex: 1 0 0` within the cave, which distributes space evenly.

## State-differs invariants

Linelayout has no interactive state model. There are no hover, focus, selected, or disabled states on the layout container or its children. The only state toggle is:

- **`pointVisible` hidden vs visible.** When `.z-lineitem-point-hidden` is present, the point must occupy the same space but not be visible (`visibility: hidden` semantics). The connector line must remain continuous — the hidden point must not break the line's visual continuity.

## Notes

- **Virtual parent architecture.** The first/last area `<div>`s start life inside `.z-lineitem` in the mold output, but are physically moved to `.z-linelayout-first` / `.z-linelayout-last` at `bind_()`. A CSS selector like `.z-lineitem > .z-lineitem` (direct child) targets these moved elements IN THEIR POST-BIND POSITION (inside first/last columns, not inside the cave lineitem). The evaluator must inspect the live DOM, not the mold output.
- **The base class `.z-lineitem` is reused for the area `<div>`s.** The first/last area containers emitted by `encloseChildHTML_()` use `class="' + this.$s() + '"` which resolves to `.z-lineitem`. This means `.z-linelayout-first > .z-lineitem` and `.z-linelayout-last > .z-lineitem` are valid selectors for targeting content slots — they are NOT the lineitem root itself (which also carries `.z-lineitem`). Avoid styling `.z-lineitem` globally with layout properties that would break the content-slot divs.
- **`z-index` values are JS-managed.** `.z-linelayout-line` gets `z-index: 99` and `.z-lineitem-point` gets `z-index: 100` from ZK's CSS. A theme that applies `isolation: isolate` or a `position` + `z-index` on `.z-linelayout-cave` without a new stacking context may cause the line to paint over points.
- **`lineStyle` and `pointStyle` are author inline-style overrides.** Authors can pass raw CSS string via `lineStyle="background: red"` on the linelayout and `pointStyle="border: 2px solid green"` on any lineitem. Theme CSS rules will be overridden by these inline styles — this is intentional for customization. The theme must accept that per-item point appearance may be overridden.
- **No `disabled` attribute.** Neither `Linelayout` nor `Lineitem` support `disabled`. There is no `.z-linelayout-disabled` or `.z-lineitem-disabled` class in the ZK source.
- **Model binding.** When used with `model="${...}"`, the linelayout renders lineitem children via a `<template name="model">`. The DOM produced is identical to manually-defined children. No extra wrapper classes or state classes are introduced by model rendering.
